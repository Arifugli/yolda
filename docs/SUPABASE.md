# MVP: Supabase + Render, только через браузер

Supabase обслуживает PostgreSQL и приватные фотографии. Next.js/API запускаются на Render как Docker web service. Supabase не является хостингом полноценного Next.js-сервера. Вход пока использует существующие HttpOnly-сессии Yolda; Supabase Auth не подключён.

Проект пользователя: `https://kmpkfgenbomkbdzwpfbx.supabase.co`. Адрес публичный; ключей и паролей в репозитории нет. Реальная миграция этого проекта и публикация Render не выполнены без серверных настроек и доступа к аккаунту хостинга.

## 1. Подготовить Supabase

1. Откройте свой проект в Supabase Dashboard. Если он обслуживает другое приложение, используйте отдельный проект для Yolda. Миграции создают таблицы в `public` и закрывают к ним прямой доступ браузерных клиентов; не применяйте их к чужой схеме.
2. Откройте [supabase/bootstrap.sql](../supabase/bootstrap.sql) в GitHub и скопируйте содержимое в Supabase SQL Editor. Выполните от имени `postgres`. Скрипт содержит только схему, не аккаунты и не секреты. Он применяет каждую миграцию один раз в транзакции. Предварительная проверка отказывает при конфликте с таблицами другого приложения.
3. В панели **Connect** скопируйте PostgreSQL connection string для **Session pooler**, порт 5432. Подставьте пароль базы, URL-кодируя спецсимволы в пароле. Это `DATABASE_URL`. В IPv4-средах не выбирайте direct connection без подтверждённой IPv6-связности.
4. В настройках API keys найдите серверный `service_role` либо секретный `sb_secret_...` ключ. Он нужен только серверу. Обычный publishable/anon-ключ не подходит. Не отправляйте ключ в чат и не помещайте его в GitHub или переменные `NEXT_PUBLIC_*`.
5. В SQL Editor можно отдельно сгенерировать ключ шифрования:

   ```sql
   select encode(gen_random_bytes(32), 'hex');
   ```

   Если функция находится в схеме `extensions`, используйте `extensions.gen_random_bytes(32)`. Полученные 64 hex-символа сохраните в защищённых переменных хостинга как `APP_ENCRYPTION_KEY`; храните его отдельно от резервной копии базы и сохраняйте между развёртываниями.

Приватный bucket `yolda-private` приложение создаёт при первом запуске. Если создаёте его вручную, отключите public access. Прямые политики на чтение для `anon`/`authenticated` не нужны: сервер проверяет участника и выдаёт фото через `/api/files`.

## 2. Поднять сервер приложения на Render

1. Зарегистрируйтесь на [Render](https://dashboard.render.com/), подключите GitHub и предоставьте доступ к `Arifugli/yolda`.
2. Создайте **Blueprint** из этого репозитория, ветка `main`. Конфигурация уже в [render.yaml](../render.yaml). Она предусматривает платный Starter web service; проверьте стоимость в панели перед созданием. Хостинг и географию Supabase выбирайте с учётом задержки между ними.
3. Заполните защищённые переменные:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | URI Session pooler из Supabase |
   | `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ Supabase |
   | `APP_ENCRYPTION_KEY` | Постоянный 64-символьный hex-ключ из предыдущего шага |

   Остальные базовые параметры заданы в Blueprint. Общий пароль демоверсии `DEMO_ACCESS_PASSWORD` Render генерирует сам; сохраните его из защищённых настроек. Общий логин — `demo`.
4. Начните развёртывание. Образ собирается, проверяет конфигурацию/существующую схему, применяет недостающие миграции, готовит bucket и добавляет вымышленные демо-аккаунты. Health check — `/api/health`.
5. Когда Render покажет HTTPS-адрес, добавьте в Environment переменную `APP_ORIGIN` с этим адресом **без завершающего слеша**, например `https://имя-сервиса.onrender.com`, и перезапустите развёртывание. При смене домена обновляйте `APP_ORIGIN`.
6. Откройте сайт, введите общий логин/пароль, затем войдите демо-аккаунтом. Код SMS отображается в интерфейсе. Пройдите поездку двумя независимыми браузерными профилями/устройствами. Физически один браузерный профиль не может одновременно иметь две разные сессии Yolda.

Для фото и ключей не используется временный диск Render: фотографии находятся в Supabase Storage, ключ шифрования — в защищённой переменной. При отсутствии общего пароля Supabase-демоверсия закрывается HTTP 503. `/api/health` остаётся доступен без пароля и проверяет только БД, не весь бизнес-цикл.

## 3. Проверить подключение и ошибки

На хостинге с доступной shell либо в доверенной облачной консоли с этими переменными выполните `npm run supabase:check`. Команда проверяет TLS базы, наличие миграций/RLS, приватность bucket, запись/чтение/удаление проверочного изображения. Реальные ключи в вывод не попадают. Эта проверка пока не запускалась против проекта пользователя.

- Ошибка БД: проверьте URI Session pooler, пароль, доступность проекта и настройки сетевых ограничений Supabase.
- Ошибка сертификата: используйте официальный корневой сертификат проекта в `DATABASE_CA_CERT`, если он требуется. Поддерживаются переносы строк или `\n`. Не отключайте проверку TLS.
- Ошибка Storage 401/403: проверьте серверный ключ и проект. Public bucket намеренно отклоняется.
- Ошибка «Недопустимый источник запроса»: `APP_ORIGIN` должен в точности совпадать с адресом сайта.
- Build/старт: смотрите Logs в Render. Секреты и URI базы не публикуйте при пересылке ошибки.

Параметры `APP_MODE=demo` и `DEPLOYMENT_ENV=development` сохраняют явную симуляцию провайдеров. `NODE_ENV=production` относится к оптимизированному Next.js и не означает готовность реальных SMS/платежей/MyID. Переключение `DEPLOYMENT_ENV=production` заблокирует демо-провайдеры, а не подключит настоящие.

## Такси, груз и спецтехника

- **Такси:** водитель добавляет легковую машину/минивэн, подтверждает доступ к машине и проходит демо-проверку личности. В блоке «Я водитель такси» выбирает машину, разрешает геолокацию и выходит на линию. Приложение должно оставаться на экране; обновления каждые 20 секунд, срок позиции 120 секунд, допустимая погрешность до 200 м. Выход с линии удаляет текущую позицию. История перемещений не собирается.
- Заказчик указывает адреса и две точки на OpenStreetMap, рассчитывает и принимает фиксированную цену MVP: `max(10000, округление вверх до 1000(7000 + 2500 × км по прямой))` сум. Это не дорожный километраж, не оценка времени подачи и не списание денег. Автопоиск выбирает ближайшую свободную подходящую машину до 8 км, исключая собственный заказ, устаревшую позицию и занятых/ограниченных водителей. На принятие — 45 секунд; отказ/истечение исключает этого водителя для данной заявки и продолжает поиск при следующем опросе заказчика или heartbeat водителя. Для подачи позже поиск начинается за 20 минут. Публикация и heartbeat также запускают серверный подбор: заказчик может закрыть карточку. Отдельной фоновой диспетчерской очереди и push пока нет.
- После принятия: прибытие → код заказчика на 5 минут/5 попыток → поездка → сообщение водителя о завершении → подтверждение заказчика. Отмена до начала, отказ водителя, чат, споры/аудируемая поддержка и взаимные отложенные отзывы.
- **Грузы/спецтехника:** заказчик выбирает категорию, характеристики, адрес/маршрут, время и бюджет за весь заказ. Исполнители предлагают цену на своей машине. Заказчик выбирает предложение. Масса, места и характеристики крана проверяются сервером; изменённые параметры и ограничения повторно проверяются при назначении. Самосвалы доступны для перевозок и работ, фуры — для перевозок, краны/экскаваторы/погрузчики — для работ.
- Один профиль может заказывать одну услугу и выполнять другие. Одновременно у исполнителя допускается только один активный заказ этих новых направлений. Публичный поиск показывает отдельно введённое краткое описание и характеристики; скрывает точные адреса, координаты, подробное описание и участников. После назначения сведения доступны участникам; чтение поддержкой аудируется.

Это демонстрационный MVP: подтверждение разрешений/документов исполнителя пока является его декларацией, не государственной проверкой. Не подключены дорожная маршрутизация, постоянное фоновое отслеживание, push и финансовые операции новых услуг. Открытые тайлы OSM требуют соблюдения политики использования; при росте нагрузки подключите подходящего провайдера тайлов. Резервные копии БД и Storage настраиваются отдельно: резервная копия PostgreSQL не содержит байты фотографий.
