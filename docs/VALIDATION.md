# Исправление Render TLS — 26 октября 2026

В предоставленных логах Render сборка Next.js завершилась успешно, а запуск остановился в `supabase:preflight` с `SELF_SIGNED_CERT_IN_CHAIN`. Исправлено доверие цепочке PostgreSQL Supabase: официальные production CA 2021/2025 включены в образ и автоматически используются только для официальных DB/pooler-хостов. Источник и fingerprints: [certs/README.md](../certs/README.md). `DATABASE_CA_CERT` остаётся явным override; проверка цепочки и hostname не отключается, URI SSL-параметры не могут её заменить.

Проверено: TypeScript; Docker-сборка/запуск с новой базой; наличие обоих сертификатов внутри образа; 54 серверных теста без пропусков. Шесть новых тестов включают реальные TLS-handshake: доверенный CA принимается, недоверенная цепочка и неверное имя сервера отклоняются. Логины/права/доставки/такси проверены серверным регрессионным набором; браузерный набор ранее прошёл и в этой правке повторно не запускался.

Удалённое подтверждение успешного Render deploy пока отсутствует: API Render возвращает 401 без предоставленного доступа; первоначальный запрос публичного `yolda-mvp.onrender.com` заблокирован egress-прокси. Наличие исправления и успешная локальная сборка не объявляются подтверждением живого сайта. Отсутствие `.env` в контейнере штатно: Render передаёт настройки процессу.

## Пять браузерных сценариев

1. Три разные сессии: создать отправление через форму, оплатить/опубликовать, отклик/выбор, код отправителя, движение, код получателя, завершение, чат и запись отзыва.
2. Экран 390×844 без горизонтальной прокрутки; посторонний получает HTTP 403 на чужую карточку.
3. Настоящий PNG загружается через API в S3, владелец читает его, посторонний получает 403; после явного назначения аватаром профильная фотография доступна зарегистрированным пользователям. Поддельный MIME отклоняется HTTP 400.

4. Измененное в настройках название появляется в интерфейсе, метаданных HTML и PWA manifest; тест восстанавливает исходное название.
5. Ответ о создании потерян после серверного commit, пользователь повторяет действие; frontend сохраняет Idempotency-Key и в базе остается ровно одно отправление.

Дополнительно проверены автоматическое освобождение истекшей брони при новом резервировании, сохранение занятости физически заполненной ячейки после срока хранения, возврат из исходной точки до отмены, запрет команды двери без подтвержденной брони/наличия, отзыв прав получателя после выдачи кода, применение времени поездки к срокам заказов и отказ принимать демо-verified в production.

## Исправленные проблемы среды

- npm cache изначально указывал в недоступный домашний каталог; установка использует writable `/workspace/.npm`.
- Для dev-ресурсов Next.js добавлен конкретный разрешенный origin 127.0.0.1; проверка POST учитывает реальный Host и конфигурируемый APP_ORIGIN.
- BuildKit не разрешал hostname egress-прокси и не доверял его TLS-сертификату. Cloud helper передает существующий маршрут/DNS и доверенный публичный CA как build secret. Проверка TLS, хеши lockfile и подписи запросов не отключались.
- Приватный S3-эмулятор использует только path-style адресацию. Каталог объектов создается в образе с владельцем node до первого монтирования нового тома; доступ на запись проверяется при старте.
- Одновременные dev-серверы с общим `.next` и переустановка пакетов во время работы приводили к ошибкам загрузки. Проверка повторена на отдельном Compose-приложении; запускать следует один dev-сервер на checkout.
