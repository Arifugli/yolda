# Yolda

**Мобильный интерфейс:** главная с услугами, карта, поиск адреса и короткий заказ такси/доставки. Подробности: [docs/MOBILE.md](docs/MOBILE.md).

Мобильное PWA для доставки посылок, такси, грузоперевозок и спецтехники в Узбекистане. Один профиль может заказывать услуги и выступать исполнителем. Такси автоматически подбирает ближайшего свободного водителя по свежей геопозиции; грузовые машины и спецтехника работают через предложения исполнителей. Это демонстрационный MVP; реальные финансовые и идентификационные провайдеры не подключены.

**Запуск через браузер с Supabase и Render:** [docs/SUPABASE.md](docs/SUPABASE.md). SQL для панели Supabase: [supabase/bootstrap.sql](supabase/bootstrap.sql). Конфигурация хостинга Next.js: [render.yaml](render.yaml). Supabase обслуживает PostgreSQL и приватные фотографии; сервер приложения размещается отдельно.

## Запуск

Требования: Node.js 24, npm, Docker с Compose. Версии зависимостей фиксирует `package-lock.json`.

```bash
cp .env.example .env
npm ci
docker compose up -d db
npm run storage:dev
```

Последняя команда запускает отдельный S3-совместимый эмулятор для разработки. В другом терминале, в корне репозитория:

```bash
npm run db:migrate
npm run storage:prepare
npm run db:seed
npm run dev
```

Откройте приложение на порту 3000. Для оптимизированного приложения: `npm run build && npm start`. Локальный адрес нужен для самостоятельного запуска; облачный onboarding не создает публичного предпросмотра.

Вариант целиком в контейнерах:

```bash
docker compose up --build -d --wait
```

Compose запускает PostgreSQL, приложение и отдельный S3-совместимый эмулятор. База и фотографии сохраняются в именованных томах. Не запускайте одновременно локальное приложение и Compose-приложение на порту 3000 либо локальное хранилище и Compose-хранилище на порту 9000. `docker compose down` сохраняет данные; `down -v` удаляет их и не является обычным способом остановки.

В этой облачной среде Docker build требует DNS-настройки существующего egress-прокси и его доверенного публичного CA. Проверенный вариант: `npm run cloud:compose` вместо обычной команды Compose. Скрипт создает вспомогательную конфигурацию под `/workspace/yolda-environment-build`, передает публичный CA как BuildKit secret и не сохраняет учетные данные прокси. TLS и подписи пакетов остаются включенными. Для параллельной проверки можно задать APP_PORT, DB_PORT, STORAGE_PORT и COMPOSE_PROJECT_NAME. Для обычной машины без такого прокси используется стандартная команда выше.

Название меняется в административных настройках (`settings.name`) и применяется к интерфейсу входа, приложению, заголовку страницы и PWA manifest. `NEXT_PUBLIC_APP_NAME` — резервное название до подключения базы. Сервер хранит UTC, интерфейс форматирует Asia/Tashkent; суммы — целые узбекские сумы.

## Пройти первую доставку

Вход предлагает вымышленные аккаунты. Получение SMS симулируется, код показан на экране и действительно проверяется сервером. Откройте три отдельных профиля браузера/приватных окна, чтобы сессии не заменяли друг друга.

1. Азиза (`+998900000000`) создает посылку, получатель — Дилноза (`+998900000002`). В форме выберите две точки «Человек», один город, адреса, описание, вес, размеры и условия. Подтвердите допустимость содержимого и упаковку. Сначала создается черновик; оплатите через демо-провайдер и опубликуйте.
2. Бехруз (`+998900000001`) открывает «Заказы рядом», выбирает Фергану и задает поездку и отправляет отклик. Азиза выбирает его в карточке заказа.
3. Бехруз открывает «Мои доставки → Доставляю», прибывает на забор. Азиза нажимает «Передать посылку», получает одноразовый код. Бехруз вводит его и принимает посылку.
4. Бехруз переводит доставку «В пути → Прибыл в точку назначения → Передать получателю».
5. Дилноза открывает «Мои доставки → Получаю», создает код получения. Бехруз подтверждает передачу этим кодом. Дилноза нажимает «Подтвердить получение». Только теперь заказ завершен и появляется начисление курьеру.
6. Участники оставляют отзывы; встречные оценки публикуются после ответа обеих сторон или через семь дней.

Поддержка: `+998900000007`, финансовый сотрудник: `+998900000008`. Администратор: `+998900000004`, оператор пунктов: `+998900000005`, непроверенный пользователь: `+998900000006`. Пользователь Сардор (`+998900000003`) подходит для проверки доступа постороннего и второго отклика. Все номера и имена предназначены только для демонстрации. Новая регистрация подтверждает только телефон; проверка личности в профиле — отдельное действие. Совершеннолетие проверяется сервером демо-провайдера.

Начальные данные содержат четыре опубликованные демо-посылки, по одной для Ферганы, Коканда, Андижана и Намангана; это четыре независимых внутригородских маршрута. Повторный seed не дублирует аккаунты и посылки.

## Что работает

- Телефонная регистрация и вход с истекающими кодами и ограничением попыток; HttpOnly-сессии, выход и ограничения аккаунта.
- Единый профиль, транспорт, город, прием заказов, язык, уведомления, отдельная статистика и рейтинги отправителя/курьера.
- Проверка личности через `IdentityProvider`, только сервер меняет результат; демо-провайдер без биометрии и документов.
- Черновик, проверка содержимого/размеров/зоны, расчет тарифа, согласие получателя-плательщика, оплата до назначения.
- Приглашение получателя секретным токеном; номер заказа не дает доступа. Приглашение для известного аккаунта нельзя забрать другим пользователем.
- Поиск курьеров и заказов по поездке; приблизительные расстояния и отклонение явно подписаны. Точные адреса отсутствуют в поисковой выдаче.
- Отклики и атомарное назначение одного курьера; нельзя доставлять собственный заказ.
- Серверная машина состояний, ответственность и история передач; ограниченные одноразовые коды для забора, получения и возврата.
- Все девять комбинаций трех типов точек в модели; симуляция резервирования, помещения, изъятия и сбоев постамата. Операции пункта требуют отдельного подтверждения его сотрудником.
- Текстовый/фото-чат, лента событий, SSE-обновления, уведомления в приложении, жалобы и скрытие сообщений сотрудником поддержки.
- Приватные фотографии через серверную авторизацию и S3-адаптер; PNG/JPEG/WebP до 5 МБ, декодирование, лимит 20 Мп, удаление метаданных.
- Координаты курьера передаются только по отдельному действию с согласием во время активной доставки. Непрерывное фоновое отслеживание не обещается.
- Отмена до забора, отказ курьера до забора, фиксация неудачной доставки, согласованный возврат с кодом отправителя.
- Споры с фото-доказательствами, независимое состояние спора, блокирование еще не выплаченного начисления, решение администратора.
- Демонстрационные начисления, выплаты и возвраты; раздел дохода не является банковским кошельком.
- Панель администратора с реальными запросами к базе, тарифами/лимитами/зонами, ролями поддержки/оператора/финансов/администратора и аудитом.
- PWA manifest, адаптивная навигация, страница без интернета. Чувствительные API-ответы и фотографии не кешируются service worker.

## Проверки

```bash
npm run typecheck
npm test
npm run build
# Приложение должно быть запущено отдельно; Chromium уже доступен в облачной машине.
npm run test:e2e
```

`npm test` запускает реальные транзакции PostgreSQL и проверяет критические запреты, конкурентное назначение, полный цикл, коды, повторную оплату, возврат, спор, симулятор, сбои и подтверждение оператором. Создаваемые тестовые пользователи и заказы удаляются после проверки. Запускайте на отдельной тестовой/демо-базе: тесты симулируют неисправности демонстрационных постаматов.

Playwright использует `/usr/bin/chromium`; путь можно изменить через `CHROMIUM_PATH`. Если браузера нет, установите совместимый Chromium или `npx playwright install chromium` и настройте путь. Браузерная проверка проходит полный цикл тремя сессиями, чат, отзыв, мобильный экран, приватность фото, изменение названия и восстановление после потери ответа. Она сбрасывает только счетчики запросов SMS семи вымышленных демо-аккаунтов и создает демонстрационный заказ. В production эти тесты запускать нельзя.

Результаты текущей проверки записаны в [docs/VALIDATION.md](docs/VALIDATION.md). Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). API: [docs/API.md](docs/API.md). Эксплуатация и подготовка пилота: [docs/PILOT.md](docs/PILOT.md).

## Симуляции и пределы первой версии

Реальные SMS, MyID, эквайринг, возврат/выплата денег, push/email и аппаратные постаматы не подключены. `APP_MODE=demo` требуется явно; `DEPLOYMENT_ENV=production` запрещает демо-адаптеры. Отсутствие реального провайдера вызывает ошибку, автоматической подмены нет. Production-интеграции пока не реализованы и не готовы к запуску.

Объектное хранилище в демо — отдельный S3-совместимый эмулятор S3rver, не production-сервис. `lib/storage.ts` позволяет подключить закрытое S3-совместимое хранилище настоящего оператора. Локальный файловый fallback допустим только в явном демо-режиме. Браузер никогда не получает S3-ключи.

Карта — схема реальных введенных координат, не картографический сервис. Отсутствуют дорожная маршрутизация, оптимизация нескольких посылок, последовательные курьеры, межгород и бизнес-кабинет; они относятся ко второму этапу. Поля адресов/цены после назначения через API менять нельзя.

Русский и узбекская латиница доступны для навигации, форм, действий, статусов и основных административных подписей. Введенные пользователем названия/описания не переводятся; отдельные динамические сообщения сервера и симулятора пока остаются на русском и требуют языковой приемки перед пилотом.

Публичное отслеживание через отдельный секретный токен возвращает только статус и время, без контактов, адресов или геолокации. Его API готов; отдельный публичный экран еще не оформлен. QR-изображения не генерируются: используется разрешенная спецификацией альтернатива — одноразовый код.

MyID, OneID и MyGov не смешиваются. Официальные материалы MyID необходимо получить у провайдера; в этой машине обращения к `myid.uz` и `docs.myid.uz` возвращали отказ сетевого прокси. Неизвестные endpoint, подписи и атрибуты не выдуманы. Контракт адаптера — точка расширения, а не готовая MyID-интеграция.
